Pagerless {{ .Chart.AppVersion }} is installed in namespace {{ .Release.Namespace }}.

The cluster identity is read-only. Pagerless reads failures and proposes every
remediation as a pull request; it never writes to a workload, Event, or Node.

{{- if .Values.rbac.watchAllNamespaces }}

Watching: every namespace through ClusterRole {{ .Release.Name }}-pagerless-read.
{{- else }}

Watching: {{ join ", " .Values.rbac.watchNamespaces }} through a read Role per namespace.
{{- end }}

{{- if .Values.credentials.existingSecret }}

Credentials are managed externally by Secret {{ .Values.credentials.existingSecret }}.
Required keys:

  AI_BASE_URL, AI_API_KEY, AI_MODEL
  GITHUB_TOKEN, GITHUB_REPO
  CONNECTOR_<NAME>_TOKEN              (one per configured connector)
{{- else }}

Credentials live in Secret {{ .Values.credentials.secretName }}, with every key
present and empty. Fill it before the first Page can be investigated:

  kubectl -n {{ .Release.Namespace }} edit secret {{ .Values.credentials.secretName }}
{{- end }}

The Portal and its sign-in are delivered with the authentication and Portal
slices. This release serves the agent report API and the metrics API:

  kubectl -n {{ .Release.Namespace }} port-forward svc/pagerless-server 8080:{{ .Values.service.port }}

Record a decision on a Page by patching its annotations, or with the CLI:

  kubectl page approve <page>
  kubectl page dismiss <page> --reason "<why>"

Role pagerless-approver in this namespace grants exactly that permission. Bind
it to the people who may record decisions.
