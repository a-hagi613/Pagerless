Pagerless is installed as release {{ .Release.Name }} in namespace {{ .Release.Namespace }}.

The dashboard and the API are served privately by the Service
{{ include "pagerless.fullname" . }}-server on port {{ .Values.service.port }}.
Open the dashboard with:

  kubectl --namespace {{ .Release.Namespace }} port-forward service/{{ include "pagerless.fullname" . }}-server {{ .Values.service.port }}:{{ .Values.service.port }}
  open http://localhost:{{ .Values.service.port }}

Sign in with the operator token from the Secret {{ .Values.existingSecret }}
(the key named {{ .Values.secretKeys.operatorToken }}). Install the CLI separately:

  kubectl krew install page
  kubectl page "Why is checkout timing out?" -n shop

Readiness is deliberate. The Service stays private, and the pod is not Ready
until every prerequisite answers:

  kubectl --namespace {{ .Release.Namespace }} get pods
  kubectl --namespace {{ .Release.Namespace }} logs deployment/{{ include "pagerless.fullname" . }}-server
  kubectl --namespace {{ .Release.Namespace }} port-forward service/{{ include "pagerless.fullname" . }}-server {{ .Values.service.port }}:{{ .Values.service.port }}
  curl --silent http://localhost:{{ .Values.service.port }}/readyz

The readiness body names the failing check. The usual causes and retries are:

  - PAGERLESS_MODEL_BASE_URL / model.name: the endpoint or model name is wrong,
    the key is missing, or the model does not support tool calls. Correct the
    values and run `helm upgrade` with the same release. No test pull request is
    created to check the model.
  - github_read / github_publish: the repository, base branch, path prefix or a
    token is wrong. The read token needs repository contents read access; the
    write token needs contents write and pull-request write access. Update the
    Secret out of band, then restart the deployment so the projected files are
    re-read.
  - kubernetes_mcp: the read-only ClusterRole or Role bindings are missing.

The chart references the externally provisioned Secret {{ .Values.existingSecret }}
and never creates or edits it. Supply every key named in values.secretKeys before
installing. The transcript keeps pages for {{ .Values.retention }} and then
deletes them, including their events, evidence and proposals.

Pagerless never applies a change to the cluster and never merges. A proposal is
a draft pull request against {{ .Values.github.repository }} that a human reviews.

The Kubernetes integration reads every namespace with a read-only ClusterRole.
Set kubernetes.namespaceAllowlist to install one Role per namespace instead.
{{- end }}
