# pagerless-executor manifests

A kustomize base that deploys `pagerless-executor` into the `pagerless` namespace: its service account, its RBAC, the Service, and the Deployment. It belongs beside `deploy/pagerless-server`, whose base creates the namespace and the CRDs, so deploy that base first.

- **Write credentials.** The Executor holds the only write credentials in Pagerless (ADR-0005): the `pagerless-executor` service account and the write-scoped GitHub token (ADR-0015). The token is read from the `token` key of the Secret `github-write` in the `pagerless` namespace, mounted as a file and read again for every request, so a rotated Secret takes effect without a restart.
- **Sandbox.** The Deployment reads the Sandbox's git URL from the key `url` of the ConfigMap `pagerless-sandbox`. When `--sandbox-url` (`SANDBOX_URL`) is set, the Executor derives the GitHub repository from that URL unless the optional `githubRepository` key supplies an explicit owner/name through `PAGERLESS_GITHUB_REPOSITORY` (set that value in the bootstrap configuration when a custom Git service uses a URL path beyond owner/name). When `--sandbox-url` is empty, the Executor starts in live-only mode without GitHub configuration: `RestartWorkload` executes against the cluster (`NoAction` needs no execution), and pull-request Actions (`Scale`, `PatchResources`, `Rollback`) are refused with `412 Precondition Failed` (`UnsupportedAction`). Both the ConfigMap and the Secret must exist in the kustomize base before the pod starts.
- **RBAC.** The Executor may only `get` and `list` Triages and TriageApprovals, create TokenReviews, and, in the `sandbox` namespace, read Deployments, StatefulSets and pods and delete pods. It cannot write Triage status, which only `pagerless-server` writes (ADR-0001), and it cannot create a TriageApproval, which only a human does (ADR-0004).
- **Caller.** The Executor accepts one caller, `pagerless-server`, which authenticates with a projected service account token whose audience is `pagerless-executor`. The server's Deployment projects that token.
- **Approval.** Before it commits anything, the Executor confirms that the Triage is Approved, that the stored Proposal still hashes to the requested hash, and that a TriageApproval exists for exactly that hash (ADR-0014). It refuses a patch that does not apply cleanly to its base commit, that changes more than the one file the Proposal names, or that touches `.github/` (ADR-0008).
- **Delivery.** A pull request change goes to the branch `pagerless/<triage>-<hash prefix>` as one commit, with a pull request into the Sandbox's branch and auto-merge enabled with the squash method (ADR-0011). The Sandbox repository must allow auto-merge, and its branch protection must require the `kubeconform` check and allow the Executor's token to open pull requests. RestartWorkload executes live instead: the Executor deletes the Workload's pods one at a time, waits for each replacement to be ready, and confirms that the rollout is available. Deleting pods changes no manifest, so Argo CD reports no drift and self-heal has nothing to revert (ADR-0002).
- **Images.** The Deployment references `ghcr.io/a-hagi613/pagerless-executor` at version `0.1.0`. The image must include `git`.
