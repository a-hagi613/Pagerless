# Pagerless 1.1.0

Pagerless 1.1.0 adds observability integrations and an automation entry point. The
investigation API, the read-only Kubernetes boundary and the draft pull-request
contract are unchanged.

## Observability MCP

Two optional read-only MCP integrations ship with the chart:

- **Prometheus** — `prometheus_query`, `prometheus_alerts`, `prometheus_targets`.
- **Grafana** — `grafana_alerts`, `grafana_dashboards`, `grafana_dashboard`,
  `grafana_datasources`.

Each integration is a separate process with its own bearer token. The server
admits only the named tools through the same policy, redaction and transcript as
the Kubernetes and GitHub integrations. Enable them with the `observability`
values documented in the README.

## Automatic investigations

The server now serves an authenticated MCP endpoint at `/mcp`:

- `pagerless_investigate` starts a page and a turn from a question, namespace and
  optional `{kind, name}` target. An optional idempotency key deduplicates an
  alert retry.
- `notifications/pagerless/investigate` accepts the same payload as a push-style
  MCP notification.

The endpoint uses the installation's `trigger-token` when it exists and falls
back to the operator token for an installation that has not added the key.

## Documentation and branding

The README is rewritten around the CLI, the dashboard, draft pull requests and
the observability path. The mascot is restored as the project logo. Release
notes, install snippets and image coordinates move to 1.1.0.

## Upgrade from 1.0.x

```sh
helm upgrade pagerless oci://ghcr.io/a-hagi613/pagerless/core/charts/pagerless \
  --version 1.1.0 --namespace pagerless --reuse-values
```

Add `trigger-token` to the installation Secret if you use the MCP automation
endpoint without the operator token:

```sh
kubectl --namespace pagerless patch secret pagerless-credentials \
  --type merge --patch "{\"stringData\":{\"trigger-token\":\"$(openssl rand -hex 32)\"}}"
```
